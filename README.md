# ADK — AI Development Kit

ADK 是一套面向真实软件工程的、可复用的 AI 开发规范与技能套件。它将通用工程规则、技术栈规范、按需加载的 Skills、项目适配配置和可执行验证机制组织为独立版本化资产，供不同代码仓库复用。

## 目标

- 提高 AI 在既有工程中的理解、实现、调试、验证与交付质量。
- 降低需求误解、越界修改、未经验证即宣称完成、以及反复人工纠偏的发生率。
- 支持 Qt/QML、C++/CMake、Go、嵌入式与 MCU 等工程，并允许项目保留自己的架构与约束。
- 从 Huayan 与 HyRemote 的真实开发经验中提炼通用实践，以试点结果驱动迭代。

## 非目标

- ADK 不是 Agent 运行时、任务调度系统或模型服务。
- ADK 不替代项目自身的架构文档、测试、CI、安全政策或人工决策。
- ADK 不要求所有项目采用同一技术栈、目录结构、分支策略或阶段门。
- ADK 不把未经验证的经验直接升级为强制规则。

## 核心组成

1. **Core Rules**：工程事实优先、范围控制、安全边界、验证证据与交付要求。
2. **Skills**：项目导入、任务规划、实现、调试、构建验证、代码审查与 Git/PR 生命周期等可重复工作流。
3. **Technical Profiles**：Qt/QML、C++/CMake、Go、嵌入式/MCU 和混合系统的技术约束。
4. **Project Adapter**：把 ADK 的通用内容与项目级事实、工具及规则组合起来，不覆盖项目已有决策。
5. **Checks & Evals**：验证套件自身的结构与元数据，并通过真实任务回归测试检查行为效果。

## 状态

当前仓库处于初始建设阶段。规范与技能会先在 Huayan 和 HyRemote 中试点，再依据真实证据迭代。未经过验证的能力会明确标注状态，不宣称已经具备。

## 建设原则

- 通用规则与项目事实分离。
- 强制规则与按需技能分离。
- 要求与验证证据分离。
- 尽可能自动检查可机器判定的要求。
- 优先使用最小、可审查、可回滚的变更。
- 保留清晰的变更记录和版本兼容说明。

## 文档导航

初始架构、规则、技术 Profile、Skill 编写约定和项目接入流程将在后续变更中逐步建立。以仓库中已合并的文件为准，不以规划清单代表已经实现的能力。
